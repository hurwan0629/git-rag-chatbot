# 저장소 수집 테스트 후 리뷰

[[docs/tests/repo-ingestion/validation|테스트·검증 기록]] · [[docs/tests/repo-ingestion/final-design|현재 구현 설계]]

## 서비스 제공 시 단계별 상세 진행률 표시

- [ ] 현재 `n/5` 단계 표시에 더해, 각 단계 내부의 진행도를 `%`와 처리 개수로 표시한다.

현재 출력은 수집·청킹·추론 등의 단계만 알려준다. 파일이 많거나 모델 준비·추론 시간이 길어지면 사용자는 얼마나 처리됐는지, 작업이 계속 진행 중인지 알기 어렵다. 서비스 제공 시에는 단계 이름과 상세 작업, 진행률을 함께 보여줄 필요가 있다.

| 작업 | 표시할 정보 예시 |
| --- | --- |
| repo 경로 목록 조회 | 조회 중인 폴더·발견한 파일 수. 전체 수 확정 전에는 조회 중 상태 표시 |
| 파일 불러오기 | `파일 수집 30% · 30/100개`와 현재 처리 파일 경로 |
| tokenizer·모델 다운로드 | 전체 크기를 알 수 있으면 다운로드 bytes와 `%` |
| 모델 로딩 | tokenizer 준비·가중치 로딩·GPU 이동 등 현재 상세 상태. 측정 가능한 로딩 진행률이 있으면 `%` |
| 청킹 | `청킹 60% · 60/100문서`와 생성된 청크 수 |
| 임베딩 추론 | `추론 45% · 450/1,000청크`와 현재 배치 |
| 저장·검증·HTML 생성 | 처리 중인 산출물과 완료한 항목 수. 전체 항목 수가 확정되면 `%` |

예: `[4/5] 임베딩 추론 · 45% (450/1,000청크)`처럼 전체 단계와 단계 내부 진행도를 구분한다. `4/5`라는 이유만으로 전체 작업이 80% 완료됐다고 표시하지 않는다.

진행률은 완료한 처리 단위와 전체 대상 수로 계산하고 성공·제외·실패 건수를 별도로 표시한다. 전체 분모를 알 수 없는 작업은 임의의 퍼센트를 만들지 않고 현재 상태와 처리 개수를 보여준다. 처리 진행률이 100%여도 실패가 있다면 최종 상태는 `partial/failed`로 구분한다.

이 항목은 후속 서비스 개선 요구사항이다. 현재 테스트 코드의 진행률 출력은 변경하지 않았다.

## 코드·설정 파일 수집 범위 개선

- [x] 첫 실험의 `.py/.md/.txt` 제한을 확장해 JS/TS, Java/Kotlin, JSON/YAML 등 코드·설정 파일을 기본 대상으로 포함한다.

실제 runstop 테스트에서 확장자 제한으로 `.ts` 191개, `.tsx` 79개 등이 제외됐다. 확장자 허용은 수집 대상 선정 정책이므로 코드·설정 파일 범위를 넓혔다. 본문의 UTF-8·크기·바이너리와 자격 증명 검사는 유지한다. 새 정책은 재실행부터 적용하고 기존 run에는 당시 설정을 보존한다.
